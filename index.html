Como eu trabalho

Um método simples, com espaço para dúvida.

Não é uma receita rígida. É a ordem que costumo seguir para reduzir atalhos e deixar claro o que os dados permitem — e o que não permitem — concluir.

  1. 01

    Entender a pergunta

    Qual é a decisão ou a curiosidade por trás dos dados? O que seria uma resposta útil?

  2. 02

    Preparar e documentar

    Conheço a unidade de cada linha, trato tipos, duplicatas e valores ausentes, e registro a origem dos dados.

  3. 03

    Explorar antes de modelar

    Distribuições, relações e outliers contam a história. A EDA evita modelos bonitos para problemas mal entendidos.

  4. 04

    Comparar com uma base simples

    Começo pelo modelo mais simples que responde à pergunta. Complexidade só entra se trouxer ganho claro.

  5. 05

    Checar suposições e incerteza

    Diagnóstico, análise de sensibilidade, intervalos de confiança e tamanho de efeito fazem parte do resultado.

  6. 06

    Comunicar com honestidade

    Figuras legíveis, tabelas claras e limitações à vista. O que ficou de fora também é parte da resposta.

Duas regras que eu levo a sério: o teste é escolhido antes de olhar o resultado e “não significativo” não é prova de ausência de efeito.

Notas de dados

Ideias que eu gosto de explicar.

Três notas curtas sobre coisas que aparecem sempre quando a conversa é estatística — sem jargão desnecessário e sem prometer mais do que os dados entregam.

01 EDA antes do modelo: por que olhar os dados primeiro?

EDA (análise exploratória de dados) é o momento de conhecer o terreno: quantas linhas existem, o que cada linha representa, quais colunas têm valores ausentes, como as variáveis se distribuem e quais relações parecem suspeitas. Sem isso, é fácil escolher um modelo bonito para um problema mal entendido. Na prática, começo com perguntas simples: a base tem duplicatas? Há valores impossíveis? Os grupos são comparáveis? Outliers existem por erro ou fazem parte do fenômeno? A EDA não decide a análise sozinha, mas evita que a gente confunda pressa com método.

02 p-valor não é a probabilidade de estar certo

Um p-valor pequeno indica que os dados observados seriam improváveis se a hipótese nula fosse verdadeira — não a probabilidade de a hipótese ser verdadeira, nem o tamanho do efeito. Por isso, ao reportar um resultado, procuro mostrar também o tamanho do efeito e um intervalo de confiança. E lembro que “não significativo” não é prova de ausência de efeito: pode ser falta de precisão. A pergunta científica vem antes do teste; escolher o teste depois de ver o resultado é um atalho perigoso.

03 Dados sintéticos: para que servem (e para que não servem)

Dados sintéticos são úteis para testar um pipeline, reproduzir situações extremas e verificar se o código se comporta como esperado — sem depender de dados reais ou de uma API. Eles não servem como evidência sobre o mundo. Em projetos como o RLINE e o CAMS, os testes com dados sintéticos mostram que o software funciona; eles não representam uma cidade, uma população ou um estudo ambiental. A distinção parece pequena, mas é o que separa uma demonstração honesta de uma conclusão enganosa.
